## Resume from a hook or a job

A seat that has ended its session can now be started again when something
needs it, by a hook or a scheduled job, with no checks of the caller's own:

```
bowery resume <name> --if-dead --not-within 10m -- "3 unread letters in its box"
```

- **`--if-dead`:** when the agent is alive, or another resume of it is
  running, do nothing and exit 0. Every other refusal (no record, its
  worktree gone, a busy pane) still fails, so the caller hears about it.
- **`--not-within DUR`:** refuse an agent resumed within that long, so one
  that dies on start isn't restarted every minute. With `--if-dead`, a quiet
  exit 0.
- **`--not-within` is the last check,** so with `--if-dead` it never hides a
  refusal that needs a person (a missing worktree, no session). A `resumed`
  time bowery can't read is refused; one in the future counts as now.
- **One of `resume`, `dispatch` or `done` on an agent at a time:** two
  callers at once (two letters arriving together, or a resume racing a done
  by name, pane or worktree) can't both act on the same agent. The second is
  refused, or, for `resume --if-dead`, does nothing. The locks are files in
  the state dir's `locks/` folder, and they stay there.
- **`dispatch` of a name that already has a record is refused** ("resume it,
  or done it first"): replacing the record lost the agent's session and its
  resume count. `dispatch` also writes its record before sending the prompt,
  so a failed prompt no longer leaves a running agent unrecorded.

**Also:** `list` warns when it can't tell whether a dead agent can be
resumed, or can't count orphans, instead of dropping the line. In
`orphans --json`, a resumable agent's worktree carries `resumable` and
`resumes`.
