## What's new: the bus, and offices across machines

v0.4.0's offices could only reach each other through a shared disk. v0.5.0
connects them over the network, and adds the **bus**, so offices tell each
other what happened as it happens and nobody has to poll.

### The bus

- **`pkg/bus`**, a library other programs can import: the event envelope and
  its canonical bytes, vector cursors, the per-producer append-only log, topic
  rules and retention, the local node, and replication between regions.
- **Each producer has its own log**: a region's seat (`<region>/<seat>`) or a
  service. Its events are numbered by `seq`, signed by the producer (namespace
  `bus-event`) and sealed by its region (`bus-region`), and the log checks
  both before it appends one. A resend is dropped quietly. A fork, or a gap
  behind the head, is refused. A torn last line from a crash is cut off when
  the log opens.
- **A vector cursor** (`producer=seq,…`, sorted) says how far a reader has
  read. It fits in an SSE `Last-Event-ID`.
- **`office bus serve`** runs a region's node on a machine, on a unix socket
  under the region's var directory. The seat is the Unix user the kernel saw
  connect (`SO_PEERCRED`, Linux only so far). The node signs and seals for
  that seat, so a seat needs no key of its own. **`office bus publish`** sends
  an event as your seat. **`office bus follow`** reads from a cursor, prints
  `caught_up`, then streams each new event as it lands (inotify, with a 1 s
  backstop). A reader that stops reading is held for 1,024 records and 5 s,
  then told `resume from <cursor>`, and `follow` exits 3. **`office bus
  status`** shows the logs, the readers and each peering.
- **Topic rules** go in the region file: `[bus.seats.<user>]` `publish` and
  `read` lists, a peer's `may_publish` and `may_read` beside its `may_place`,
  and `[bus] private` topics that never leave the region. Everything defaults
  to deny. A pattern is `*`, a whole-part prefix (`job.*`) or one topic.
- **Retention per topic**, 30 days by default (`[bus] retention`,
  `[bus.retain]`). Compaction always keeps each producer's head. A cursor
  below what was dropped gets `ErrTooOld` (`410 resync`) instead of a silent
  gap.
- **Replication between regions** over `dir` or `http`. A push goes out as
  soon as the log grows, and a pull long-polls for up to 20 s, so the side
  that can reach the other makes both calls and a firewalled machine needs no
  inbound port. Each call is signed (`bus-peer`), dated to within 5 minutes
  and answered only once. Both sides check the rules. Per-peer cursors in
  `bus/peers/<peer>.json` let a restart pick up where it left off.

### Offices across machines: the http transport

- **`office serve`** listens on the machine file's `listen` address.
  `POST /placements/<box>` and `POST /replies/<asker>` file letters into the
  same boxes the `dir` transport uses, `GET /catalog/<peer>` serves the
  catalog `office publish` kept for that peer, and `POST /bus/peer` hands bus
  calls to the node. A peer's address is its endpoint's URL.
- The endpoint checks only a letter's shape (size caps, content type, one
  path segment that names a real box, at most 256 letters a box). Trust still
  comes from the signatures alone.
- A letter wakes the office's pull loop as it lands: inotify on Linux, and
  now kqueue on macOS. Over loopback, a letter is delivered in 1–2 ms and
  accepted in about 33 ms.

### Also

- **A probe from another office's user defers to the office.** In root mode,
  a job placed by one office's user into another office on the same machine
  used to wait forever. Its probe now answers deferred, the resolver plans
  over the office's catalog, and the office decides on the signed placement
  when it takes it in.
- Fixed a data race in `office serve` on the root-mode flag.
- `office check` reports an http peer address that isn't a URL, an http
  machine file with no `listen`, and a bad bus topic pattern.

## Compatibility

- Region files without `[bus]` load as before. The bus is off for any seat or
  peer the file doesn't name.
- A `dir` region keeps working unchanged. `http` is opt-in, per machine file.
- Existing dispatch records, configs and office state load unchanged.

## Upgrading

`bowery upgrade`, or the install line in the README. A root-mode office host
(`/usr/local/bin/office`) is installed by its owner, so upgrade it too. To try
the bus, see "The bus" in `docs/design.md` and the `[bus]` section of
`examples/offices/etc/region.toml`.
