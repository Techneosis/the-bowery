## What's new: offices and placement

Some work shouldn't go to a pane you pick. It belongs to an **office**: one
Unix user on a machine that holds what the job needs (repos, tools, secrets),
with rules that decide when its door is open (office hours, a gate kept by
another service, a budget). v0.4.0 adds offices, and a way to place work into
them.

**`bowery place`: the resolver.** It builds a job from flags (`--kind`,
`--needs tools=git`, `--scope`, `--pin`, `--priority`, `--ticket`, …), reads
what each office holds, asks the likely ones whether they'd take it now, and
sends a signed placement to the best one's inbox. It prints one JSON line and
exits with what happened:

| exit | line | meaning |
|---|---|---|
| 0 | `{"placed": {...}}` | sent to an office; the line names it and the job id |
| 4 | `{"queued": {...}}` | every office that could take it is closed; it waits, and `waiting_for` says on whom |
| 3 | `{"refused": {...}}` | a reserved effect: it needs a person |
| 1 | an error, or `{"unplaceable": {...}}` | no office holds what it needs: a setup gap, not a wait |

`bowery place --retry` sends waiting jobs on once a door opens (run it on a
timer: it prints `next_retry`), `bowery queue` lists them, and `bowery office
ls|describe|log|stop` asks the office host.

**`bowery dispatch <name> --job-kind <kind>`** places the job instead of
starting the agent itself: any job flag (`--job-kind`, `--office`, `--scope`,
`--needs`, `--asked-by`, `--priority`, `--pin`, `--tag`, `--surface`) makes a
dispatch a placement, with the same JSON and exits as `place`.

**The `office` host,** a second binary. It opens and closes an office
(`office open|close|clear`, with `--until`, `--kinds`, `--scope`), says what it
holds (`office describe`, `office ls`), takes in its post and starts the work
(`office pull --loop`, a long-poll that wakes when a placement lands), and
keeps a log (`office log`). It checks every placement again when it takes it
in: the signature against the office's own signers list, what it holds, and its
rules.

- **Rules are plugins** that answer open, closed or defer. A rule that crashes,
  hangs or answers nonsense counts as closed. `hours` is the reference plugin
  (weekly windows in the office's timezone). A **state-file** rule reads a
  status file another service writes, and fails closed when it is missing,
  malformed or stale.
- **Work in progress is held, not lost.** Rules keep watching while a job runs.
  When the office closes, the job yields at its next safe point, finishes its
  turn, or stops at its next turn, as the rule says; a held job keeps its work
  and resumes in place when the office opens. `office close --now` holds
  everything at once; `office stop` ends a job for good.
- **The owner decides, within limits.** `office open`/`close` override the
  rules and are logged, but a plugin that doesn't match its pinned checksum
  closes the office whatever the owner says. Decisions go to a log the office's
  own user can add to but not rewrite.
- **Every placement is signed** with the asker's SSH key (the `ssh-keygen -Y`
  format, so a signature can be checked by hand). Unsigned or unknown-signer
  placements are dropped.
- **Regions and peering.** Offices belong to a region with its own signing key.
  Two regions work together only when each declares the other, with its key
  pinned, and says which of its offices the other may use (`may_place`) and
  which extra rules that work must pass. Each publishes the other a signed
  catalog of just those offices (`office publish`); `bowery peers` shows what
  each peer published. Removing a peer's entry revokes it: new placements are
  refused and running ones are held.

`OFFICE_ROOT=<dir>` runs everything under one directory as you, to try it out.
See `docs/design.md`, "Placement into offices", and `examples/offices/`.

## Also

- `bowery watch` and its `watch.d` kinds are now in the skill, so agents use
  the watcher instead of polling.
- The README, the skill, `examples/config.toml` and tab completion cover every
  command and flag, including `place`, `queue`, `peers`, `office` and `watch`.

## Compatibility

Nothing changes unless you use it.

- `bowery dispatch` behaves exactly as before unless given a job flag. `--kind`
  is still the agent kind.
- `[placement]` in the config is optional; without it, and without a region
  file, the new commands say what's missing and nothing else is affected.
- Existing dispatch records and configs load unchanged.

## In the archives

Each release archive now holds the `office` host (`build/office`) and the
reference rule plugin (`build/rules/hours`) beside `bowery`. The installer
links `office` into `~/.local/bin` next to `bowery`. A rule plugin is installed
by an office's owner, pinned by its checksum, so the installer leaves `hours`
where it is.

## Upgrading

`bowery upgrade`, or the install line in the README. The upgrade also refreshes
the Claude Code skill and the `CLAUDE.md` notice, if you installed them; if you
upgraded with `--no-claude`, run the installer with `--claude-only` afterwards.
To set up an office, start from `examples/offices/` and `office check`.
