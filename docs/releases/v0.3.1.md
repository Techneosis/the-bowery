## Fixes to `resume`, after a review

v0.3.0's `resume` worked, but it failed untidily, and some of what its docs
said wasn't true. This release fixes both.

**`resume` changes nothing until it starts the agent.** A refused or
`--dry-run` resume now writes no record at all, not even another agent's. It
used to refresh every record's session first.

**`orphans` is read-only again.** It reads the fresh session ids but no longer
writes them. `list` and `watch` keep the records current, and each write
re-reads the record first, so a `done` that ran meanwhile isn't undone.

**A resume that fails after the agent started** now leaves a record that
points at the running agent, and says so ("is running again in ..."). Before,
the record pointed at the old pane, and the agent could be neither resumed
nor tracked. A start that fails moves a reused pane's shell back to where it
was.

**Sessions don't jump between namesakes.** A record without a terminal id (an
older one) is matched by pane, and with neither nothing is taken.

**New refusals, all before anything changes:**
- `--swarm` or `--workspace` while the agent's old pane, tab or workspace is
  still open (it would have been left owned by nothing);
- a record dispatched `--as` someone when the config no longer has an
  `identity_command` (it would have started as the wrong person), and the
  reverse on a box;
- a record from before 0.3.0, which doesn't say whether the agent was
  `--gated`: pass `--gated` or `--ungated` (new flags);
- a `--timeout` that isn't a whole number of milliseconds, and `--swarm` with
  `--workspace`.

**On a box with identities,** the directory checks and the hands-off read now
run as the agent's identity, whose directories and processes the ssh login
may not be able to see. A git failure in the checkout is an error, not "no
checkout".

**`orphans`:**
- a dead agent whose own pane is still open at a shell is now listed when it
  can be resumed (`list` already showed it);
- the resume hint warns that `done` ends it, on the record line and on the
  worktree line;
- one record whose check fails is a warning, not a whole box reported
  unreachable;
- `--json` has an `unreachable` entry for a machine it couldn't read.

**Smaller:** the prompt after `--` is taken whole (a `--machine` in it stays
in the prompt), options may come before the name, a split beside its own tab
no longer checks the neighbour pane for markers, `hands_off_env` entries must
be variable names, `list` prints `-` for an unknown sound, and dispatch keeps
the directory the agent really started in. The docs now agree on the
synopsis and the refusals.

`bowery upgrade`, or the install line in the README.
