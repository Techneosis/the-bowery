## What's new

**`bowery resume <name>`: bring a dead agent back with its conversation.**
When a dispatched agent's pane died, herdr restarted, the machine rebooted or
its tab was closed by mistake, its work is half done and its conversation is
the only record of how far it got. `resume` starts it again where it was:

```
bowery resume <name> [--swarm|--workspace] [--dry-run] [--machine LABEL] [-- <what to do next>]
```

- **Same place, same session:** the same directory and worktrees, the same
  machine and `--as` identity, the same `--gated` and `--model`, resuming its
  Claude session.
- **Where it lands:** its own pane if that is still at a shell prompt, else a
  new pane in its own tab, else a new swarm tab (or a workspace, for a
  workspace agent or with `--workspace`).
- **Its first message says it was resumed,** gives the checkout's branch and
  HEAD, and tells it to check what it already did before redoing anything.
  Anything that costs money or can't be undone is checked for, not done again.
- **It refuses, changing nothing,** while the agent or its session is alive,
  when the record has no session, when its directory or a worktree is gone, or
  when the pane it would use holds someone else's agent or a running process.
- **`hands_off_env`:** a new config key listing environment variables that mark
  a process as not yours. `resume` never lands in a pane whose shell or
  foreground process carries one.

**Records remember enough to resume.** New dispatches record the agent's
session id, directory, `--gated` and `--model`. `list`, `orphans`, `watch` and
`resume` keep the session id current (a `/clear` starts a new one). Older
records still load; without a session they can't be resumed.

**`orphans --json`.** The same findings as a JSON array, for a program. The
text output is unchanged, except that a dead record that can be resumed ends
with `(bowery resume <name>)`. `list` shows dead agents that can be resumed.
