## done takes its turn

`done` now holds the same name lock as `resume`, `dispatch` and `adopt`,
for every agent its target reaches:

- the record a name or pane resolves to (a pane by its terminal);
- the live agent's name;
- for a worktree path, every record that claims it.

A path inside a worktree counts as that worktree. It waits up to two
seconds for each lock, then refuses. Once the locks are
held, it resolves the target again and refuses if it now reaches a
different agent. `done` of a typo leaves no lock file behind. A `done` run
while a `dispatch` of the same name is midway is refused, instead of
tearing down an agent whose record isn't written yet.

`list` and `watch` take the lock to save a session they've seen change,
and skip a record someone else is holding. So a `done` can no longer drop
a record that a `list` then puts back.

## adopt fills an old record from its own agent

A record with no session or folder of its own can now be filled in from
its live agent. That covers records from before 0.3.0, and `--fresh`
starts that herdr never named. The session and the folder both come from
that one agent, and only when it sits in the record's own terminal (or,
for a record with no terminal, its own pane). A record from before 0.3.0
needs `--gated` or `--ungated`, since it doesn't say how it was started.
`adopt --ungated` over a record that says `--gated` is refused: adopt
never widens a seat.

## --ungated is for one start

`resume --ungated` on a record that says `--gated` turns off permission
prompts for that start only; the record stays gated, so the next plain
resume is gated again. The JSON line says how the start ran (`"gated"`) and
adds `"ungated_once": true`, and the text and `--dry-run` say so too.

## done of a worktree path

`done <worktree path>` used to strike the worktree from a record whose
agent had run in it, and leave the record behind. Nothing could be
resumed from that record, and it refused the next `dispatch` of the name.
That record is now dropped. A record that only listed the path as an
extra worktree still has the path struck, and is kept.

## Fails closed, and says so

- **ssh** has a connect timeout and keepalives. A machine that's asleep,
  or gone mid-call, fails the call instead of hanging a job.
- **`--timeout`** is whole milliseconds from 1 to a day (86400000), for
  `dispatch` as for `resume`. `dispatch` used to fall back to 60 seconds on
  a word it couldn't read, and a huge value wrapped the deadline into the
  past.
- **A herdr error on `tab get`** is now a failure, not "its tab is closed".
  Before, `resume` could open a second tab beside the old one, and
  `orphans` could lose track of an agent.
- **`orphans` and `list`** check a gone agent's folder as its identity,
  as `resume` does, so they no longer offer a resume that would fail. A
  failed check on one record is a warning about that record only; it no
  longer marks the whole machine unreachable. A `find` that fails on a
  machine is an error, never "no worktrees". A record that only an
  identity change blocks says resume would refuse it, and why, rather than
  "nothing left behind it".
- **`resume --json`** gives the bad first word as the name, not a later
  word or nothing.
- **`resume`** checks a recorded launcher before `--not-within`, so
  `--if-dead` can't report `too_soon` and hide a bad launcher.
- **A launched agent blocked on a screen** other than the folder-trust
  dialog fails the start, which is taken back, instead of having the
  resume notice typed into it.
- **A herdr error** while checking whether a pane is at a shell prompt is a
  failure, not "running something".
- **A sound tag that didn't take** adds `"warning": "sound_not_set"`.
- **An environment it can't read** says why: the process is gone, or this
  user can't read it.
