## `--ticket <id>`: the work item an agent is on

`bowery dispatch <name> --ticket DEV-551` records the ticket (a tracker key,
or any work-item id) in the agent's dispatch record. `resume` keeps it, and
`list --json` reports it, so a dashboard can tie each running agent to its
ticket.

- One per agent. Giving the same id twice is fine; two different ones are
  refused.
- An id is a letter or digit, then letters, digits, `.`, `_` or `-`, up to
  80 characters. Anything else is refused before anything is made.
- dispatch's JSON line gains `"ticket"` when one was given. Without
  `--ticket`, the record and the output are as before.

## `list --json`

`bowery list --json` used to be refused. It now prints one JSON array: an
object per agent on every server `list` covers (the local one, and every
machine with a record here; `--machine` narrows it to one).

- Keys: `name`, `machine` (null for the local server), `as`, `state`,
  `title`, `ticket`, `worktree`, `branch`, `dispatched_at`, `last_seen`, plus
  `pane`, `sound`, `dispatched`, `resumable`, `resumes` and `note`. A value
  that isn't there is null.
- `state` is herdr's status for a live agent (`working`, `idle`, `done`,
  `blocked`), and `gone` for a record whose agent is dead, resumable or not.
- `last_seen` is the time of the call for a live agent, and null for a gone
  one: bowery doesn't track when an agent went.
- A machine that can't be read is one entry with `state: "unreachable"`, so
  it never looks like a box with no agents.
- It doesn't count orphans (that's `orphans --json`).

`list` without `--json` prints what it always did.
